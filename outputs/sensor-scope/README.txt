Sensor Scope — просмотр четырёх источников данных MacBook

Отдельное приложение: ../SensorScope.app
1. Гироскоп — три оси, градусы/секунду.
2. Акселерометр — три оси, g. Исходные значения включают гравитацию.
3. Угол крышки — один доступный канал, дробные градусы через отчёт №7 (шаг 0,01°); отчёт №1 с шагом 1° служит запасным вариантом.

4. Освещённость — поток Apple SPU ALS (usage page 0xFF00, usage 4),
122-байтовые отчёты: lux Float32 LE по смещению 40, четыре сырых
UInt32-канала по смещениям 20/24/28/32. Внутри значения не округляются.
Формат сверялся с macimu: https://github.com/olvvier/apple-silicon-accelerometer

Переключение: верхние вкладки или стрелки влево/вправо.
Пробел — заморозить/продолжить графики. Датчики во время стоп-кадра
читаются дальше; строка частоты и текущие сырые значения остаются живыми.
«Исходный сигнал» — исходные отсчёты; «Быстрые изменения» — вычитание
плавного фона (однополюсный high-pass с коэффициентом 0,038).
Все четыре источника считываются одновременно независимо от выбранной вкладки.
Последние 8 секунд хранятся в памяти; на диск данные не записываются.

Графики перерисовываются 30 кадров/с, но получают все входящие отсчёты.
Каждая ось автоматически масштабируется отдельно, с числовой шкалой
и текущим абсолютным максимумом на видимом интервале.

Частота — число полученных отчётов за реальную секунду, не частота рисунка.
Для угла можно запросить 10, 20, 50, 100 или 200 чтений/с. Фактическая
частота может быть ниже из-за задержек чтения и планирования.
Повторное чтение одного угла не доказывает новое измерение датчиком.
Поэтому отдельно показано число изменений возвращённого значения в секунду.
Аппаратная частота обновления угла этим счётчиком напрямую не измеряется.
Шаг данных 0,01° не означает физическую точность ±0,01°. При колебаниях меньше шага и между обновлениями значение может оставаться прежним.

Проверка конкретного Mac: hardware-probe.json. Отчёт №1 вернул 125°,
отчёт №7 — 124,74°. Это два формата одного угла, не два независимых датчика.

Чтение IMU основано на LidTap by Yemcube (@yem.cube):
https://github.com/yemcube/lidtap
Лицензия включена в ../SensorScope.app/Contents/Resources/LidTap-LICENSE.txt.

Освещённость: приложение запрашивает ReportInterval=1000 мкс, получает
асинхронные HID-отчёты; повторным чтением кэша частота не накручивается.
На этом Mac измерено примерно 9,95 отчёта/с (интервал ~100,5 мс).
Это достигнутая частота доступного интерфейса, не доказанный предел чипа.
Частота ALS рассчитывается по меткам времени отчётов: (N−1)/(tпосл−tперв)
в секундных окнах. Пик потока — максимум такой частоты за сеанс.
При менее двух отчётах в окне используется число отчётов / время окна.

Минимум и максимум люксов считаются по всему сеансу, даже при стоп-кадре;
кнопка «Сбросить максимум света» начинает их отсчёт заново. Размах
на графике — максимум минус минимум за отображённые 8 секунд.
«Быстрые изменения» для света: из сигнала вычитается EMA-фон с alpha=0,25
на отчёт. Для IMU alpha=0,038. Это фильтрация графика, не новые измерения.
Паспортный предел насыщения ALS и его физическая точность неизвестны.
Сырые четыре канала внизу — отсчёты без известной калибровки в люксы.
Датчик видит освещение: тень пальца, свет экрана и лампы тоже могут давать
изменения. Для проверки тряски сравнивайте с поднесением пальца без тапа.

Проверка ReportInterval на AppleSPUHIDDriver: при запросах 100 мс, 10 мс,
1 мс и 0,1 мс получено ~9,94–9,95 отчёта/с; уменьшение интервала ниже
100 мс в этой проверке поток не ускорило. Исходный запрос 1 мс восстановлен.
